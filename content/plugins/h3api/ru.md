## Статус: устарела {#status}

**H3API помечена в этом руководстве как устаревшая.** Страница сохранена для сопровождения существующих плагинов и чтения старого кода. Для нового плагина ERA используйте [NH3API](../nh3api/): это актуальный раздел руководства с отдельной интеграцией ERA, современным CMake и явно описанными границами совместимости.

Исходный репозиторий [RoseKavalier/H3API](https://github.com/RoseKavalier/H3API) остаётся полезным историческим источником. Не смешивайте H3API и NH3API в одном проекте без тщательной проверки конфликтующих объявлений и разметки структур.

## Назначение и цель {#scope}

H3API — набор заголовочных и исходных файлов, созданный по результатам обратного проектирования исполняемого файла Heroes of Might and Magic III версии 3.2. Библиотека предоставляет C++-описания игровых структур и функций, на основе которых создавались нативные плагины.

Это низкоуровневый интерфейс к конкретной 32-битной программе. Совпадение имени структуры не гарантирует совместимость с другим EXE: перед использованием старого плагина проверяйте целевой исполняемый файл, адреса, размеры и выравнивание структур.

## Варианты подключения {#integration}

Репозиторий описывает два режима. В варианте только с заголовками подключается объединённый файл:

```cpp
#include "externals/h3api/single_header/H3API.hpp"
```

Во втором варианте H3API собирается как статическая библиотека; проект подключает основной каталог заголовков и линкуется с `H3API.lib`:

```cpp
#include <H3API.hpp>
```

Предоставленный CMake-проект фиксирует платформу x86, потому что Heroes III и описанные структуры зависят от 32-битных размеров и выравнивания.

## Сборка старого проекта {#build}

README приводит базовую последовательность CMake:

```cmake
cmake ..
cmake --build .. --config Release
```

В источнике перечислены Visual Studio 2008, 2013, 2015, 2017 и 2019 как проверенные для сборки статической библиотеки. Для более полного C++11 и лучших оптимизаций автор рекомендует Visual Studio 2015 или новее. Эти сведения описывают исходный H3API, а не гарантируют совместимость конкретного плагина с актуальной ERA.

## Переход на NH3API {#migration}

При сопровождении старого проекта сначала зафиксируйте рабочую ревизию H3API, компилятор, целевой EXE и контрольную сборку. Затем переносите код небольшими частями: типы и константы, доступ к структурам, хуки, после чего интеграцию с ERA. После каждого этапа сравнивайте размеры структур и проверяйте поведение на отдельной копии игры.

Не заменяйте include механически: одинаково названные сущности могут иметь другой namespace, контракт или поддерживаемую версию. Начните с [обзора NH3API](../nh3api/) и используйте [API ERA](../era-api/) везде, где платформенная служба уже решает задачу без прямого обращения к памяти.
