## Самостоятельная библиотека {#status}

**H3API** — самостоятельный проект RoseKavalier для создания нативных плагинов Heroes III. [NH3API](../nh3api/) разработана другим автором и имеет собственную кодовую базу и требования к C++. Выбирайте библиотеку исходя из целевого EXE, используемых объявлений и проверенной среды сборки.

Исходный репозиторий: [RoseKavalier/H3API](https://github.com/RoseKavalier/H3API). При совместном использовании H3API и NH3API проверяйте конфликты объявлений и разметку структур.

## Назначение и цель {#scope}

H3API — набор заголовочных и исходных файлов, созданный по результатам обратного проектирования исполняемого файла Heroes of Might and Magic III версии 3.2. Библиотека предоставляет C++-описания игровых структур и функций, на основе которых создавались нативные плагины.

Это низкоуровневый интерфейс к конкретной 32-битной программе. Совпадение имени структуры не гарантирует совместимость с другим EXE: проверяйте целевой исполняемый файл, адреса, размеры и выравнивание структур.

## Структура репозитория {#layout}

| Путь | Назначение |
| --- | --- |
| `include/H3API.hpp` | Основной заголовок статической библиотеки |
| `include/` | Игровые типы, функции и константы |
| `single_header/H3API.hpp` | Объединённый заголовок для подключения без сборки библиотеки |
| `CMakeLists.txt` | Конфигурация статической библиотеки для x86 |
| `doc/` | Дополнительные материалы |

Код использует пространство имён `h3`; игровые структуры обычно имеют префикс `H3`, а константы и перечисления собраны в `H3Constants`. В комментариях к полям структур автор указывает смещения и выравнивание.

## Варианты подключения {#integration}

Репозиторий описывает два режима. В варианте только с заголовками подключается объединённый файл:

```cpp
#include "externals/h3api/single_header/H3API.hpp"
```

Во втором варианте H3API собирается как статическая библиотека; проект подключает основной каталог заголовков и линкуется с `H3API.lib`:

```cpp
#include <H3API.hpp>
```

Предоставленный CMake-проект фиксирует платформу x86, потому что Heroes III и описанные структуры зависят от 32-битных размеров и выравнивания.

## Сборка {#build}

README приводит базовую последовательность CMake:

```cmake
cmake ..
cmake --build .. --config Release
```

В источнике перечислены Visual Studio 2008, 2013, 2015, 2017 и 2019 как проверенные для сборки статической библиотеки. Для более полного C++11 и лучших оптимизаций автор рекомендует Visual Studio 2015 или новее. Возможности C++11 в исходниках ограждаются `_H3API_CPLUSPLUS11_`.

## Проверка совместимости {#migration}

Для каждой сборки фиксируйте ревизию H3API, компилятор, целевой EXE и проверенные хуки. README просит подтверждать изменения адресами и примерами, документировать смещения полей и параметры функций.

Если изучаете [NH3API](../nh3api/) для похожей задачи, сверяйте контракты, пространства имён и бинарную разметку: прямой замены заголовков между независимыми проектами нет. Службы [API ERA](../era-api/) подключаются отдельно, когда они нужны плагину.
